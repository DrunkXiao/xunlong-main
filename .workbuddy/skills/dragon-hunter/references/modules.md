# 模块 A–I 实现规格

## 模块A 单股精盯

**顶部信息条**：名称、代码、最新价、涨跌额、涨跌幅、成交额、成交量、换手率、量比。成交量按手显示并附股数原值；成交额按万元/亿元自动换挡。

**图表区**：主图 K线或分时二选一，副图成交量柱，可叠加指标副图。

- K线周期：`1d / 1w / 1M / 60m / 30m / 15m / 5m / 1m`（`1m` 仅在数据源支持时出现，否则置灰并提示数据源不支持）。
- 指标：MA5/10/20/60、MACD、KDJ、RSI、成交量、成交额、换手率。
- K线配色两套（已落地）：`涨跌配色`（收盘≥开盘红，否则绿）与 `均线关系`
  （收>MA5>MA20 红 / 收<MA5<MA20 绿 / 方向不一致紫）。取等算紫，MA20 未成形的早期 K 线退回涨跌色，
  成交量柱不跟着变紫。切换写 `app_settings['ui.candle_scheme']`，三个视图共用。
- 允许用户自由组合指标与参数，组合存 `user_layouts.payload`。
- 分时图必有均价线、昨收参考线、涨停/跌停价水平线；分时成交量按买卖方向着色。

**右侧面板**：五档盘口（源不支持则显示「该数据源不提供盘口」）、逐笔成交、大单异动、概念标签、龙虎榜历史、个股事件、预警、观察笔记。

**性能**：日K 2000 根以内 60fps 拖动；切换股票时旧订阅必须解绑。

## 模块B 多股对比

布局 2 / 4 / 6 / 9 / 12，网格自适应。每格独立选周期（分时或 K 线），共享统一时间轴。

必须实现：

1. 十字光标跨图同步（同一时间刻度 + 同一价格百分比位置可选）。
2. 统一滚动与缩放，任一格操作其余跟随。
3. 按涨幅、成交额、换手率排序，支持升/降序。
4. 单格置顶、移除、一键切单股精盯（`Enter` 或双击）。
5. 布局（网格数、每格标的与周期）独立保存，可按分组保存。
6. 同板块多股横向对比入口。
7. 区间涨幅与相对强度比较：以共同起点归一化为百分比曲线，避免绝对价格误导。

对比栏字段：名称、最新价、涨跌幅、成交额、换手率、量比、今日最高、今日最低、距涨停价幅度、所属概念、异动状态。

标准化要求：涨幅与成交额对比必须可切换「绝对值 / 归一化」，避免股价与流通盘差异造成的视觉误判。

## 模块C 分时与逐笔联动

> **数据源现实**：tqcenter 不提供逐笔成交、不提供分钟K，因此本模块在当前数据源下实现为
> 「采样成交列表 + 采样分时」，联动逻辑不变，口径必须改。详见 `references/tqcenter.md`。

逐笔字段（真逐笔数据源可用时）：成交时间（毫秒）、价格、数量（股）、金额、方向（buy/sell/unknown）、来源、时间戳、质量标记。

采样成交字段（tqcenter 下）：采样时间、区间成交量（股）、区间成交额（元）、区间均价、方向推演（内外盘增量）、`quality_flag='sampled'`。界面列名写「采样成交」，行内加「推演」角标。

三向联动：

1. 点击成交行 → 分时图定位该时刻，画竖直高亮线并高亮对应分时量柱。
2. 点击分时图任意点 → 列表滚动定位到该时间窗口（默认 ±30s），并选中首条。
3. 点击大单记录 → 分时图与 K 线同时定位（K 线定位到所属分钟 bar）。

必须处理的四类脏数据：

- **毫秒时间戳**：统一转 Asia/Shanghai ISO8601 毫秒精度，禁止截断到秒导致同秒成交错序。
- **重复成交**：以 `(symbol, trade_time, price, volume, direction)` 去重；多源合并时保留优先级高的源并标记 `merged`。
- **排序**：`ORDER BY trade_time, seq`，`seq` 缺失时以到达顺序兜底。
- **多源合并**：不同源方向判定口径可能不同（外盘/内盘 vs 委托方向），合并时若方向冲突降级为 `unknown`，不得择一。

采样数据额外要求：相邻采样点间隔必须写进元数据；间隔大于 3 倍配置值时在图上断开而不是连线；
休市/停牌期间差分为 0 必须标「无新增数据」，不能画成零成交。

## 模块D 大单监控

> **口径警告**：tqcenter 无逐笔，只能按快照区间差分统计。此时 tier 表示「区间累计成交额」，
> 不是「单笔成交额」，界面与报告必须写「分钟内累计」并展示 `sampled` 标记。

四档：普通大单 / 大额成交 / 超大额成交 / 连续异动。默认阈值 100 万 / 300 万 / 500 万 / 1000 万元，用户可改，改后仅对新事件生效。

监控十项：单笔大额买入、单笔大额卖出、连续主动买入、连续主动卖出、放量上涨、放量下跌、价涨但主动卖增、价跌但主动买增、大单与价格位置关系、成交额突增。

「连续」定义：同一方向 N 笔（默认 3）且窗口内累计金额达阈值的 2 倍，N 与倍数可配置。无逐笔时改为「连续 N 个采样区间同向」。

事件标签只能取：买入活跃、卖出活跃、买卖分歧、成交放大、量价背离、资金行为不明确。标签必须由规则产生，禁止让模型自由发挥。价格位置用近 20 日区间分位：≥70% 为相对高位，≤30% 为相对低位，其余中位。

## 模块E 概念板块联动

每股关联：一级行业、二级行业、概念、热门题材、主线板块、关联核心股、板块涨幅、板块成交额、板块涨停家数、板块内强弱排名。

- 点击概念标签 → 打开该概念成分股多股对比窗（默认取涨幅前 9）。
- 板块列表排序：涨幅、成交额、换手率、涨停家数、龙头股、用户自定义。
- 龙头股判定用可解释规则：板块内涨停/涨幅居前 + 成交额居前 + 连板高度，输出排名与理由，不做主观断言。
- 板块数据缺失或延迟时，标签显示灰色「数据未更新」并给出最后更新时间。

## 模块F 龙虎榜

> tqcenter 无龙虎榜接口，本模块走 **CSV 导入**：导入时必须填 `publish_date` 与 `source`，
> 未提供则拒绝导入并提示缺哪一列。禁止用估算或历史均值补未知席位。

字段：上榜日期、上榜原因、买入前五营业部、卖出前五营业部、机构专用席位、公开披露的知名营业部、净买入额、上榜后历史表现（1/3/5/10 日）。

- 日K对应日期绘制标记（形状区分买入/卖出/净额方向），点击打开详情。
- 每条记录必须带 `publish_date` 与 `source`，未披露字段留空并在详情中注明「未披露」，严禁推测席位身份。

## 模块J 强势回调选股（已落地，见项目 README）

> 与「盯盘」不同：这是**日线收盘口径**的规则选股页，不是实时信号。数据走本地通达信 `.day`
> （`app/adapters/tdx_daily.py`），只读、不联网、不占 tqcenter 会话；扫描跑独立线程
> （`app/services/pullback_scanner.py`），40 秒级不阻塞行情轮询。

八项硬性条件缺一即剔除、评分不得补偿：近10日有效涨停 / 近10日创20日新高 / MA5>MA10>MA20 且 MA20 上行 /
回调至 MA10 或颈线 ±1.5% / 回调缩量 / 止跌形态（阳包阴·锤子线）/ 无高位放量长阴 / 收盘未破 MA20。

- 评分 100 分：板块强度 20 + 趋势 20 + 人气新高 15 + 支撑 20 + 缩量 15 + 止跌 10；`sector_score_mode: off` 时满分只有 80。
- 信号：`BUY-A`（八项全过且 ≥80）/ `WATCH` / `BLOCK`。数据超期时 BUY-A 全降 WATCH 并写明原因。
- 止损 `min(回调5日低点×0.98, MA20×0.995)` 会宽到 10%~20%，**不许偷偷收紧**，要在界面标黄并写清公式；
  股数按「1% 权益风险」与「10% 单票市值」取小、向下取整到 100 股。
- 价位线（支撑/止损/目标）落在视图外时不画贴边虚线，改为边缘标 `↑ 价`——贴边线会被读成真实价位。

## 模块K 涨停四阶段选股（已落地，见项目 README）

> 移植自 `a-share-limitup-hunter` 3.x。同样是**日线收盘口径**的选股页，数据走本地通达信 `.day`，
> 只读、不联网、不占 tqcenter 会话；扫描跑独立线程（`app/services/limitup_scanner.py`），
> 全市场 4400 只约 3.3 秒（只读 130 根、不构造 DataFrame）。

核心是**把涨停行为拆成四个可验证阶段，每个阶段只对「已经发生」的事实计分**：

```
首板发现 S1 → 三倍量确认 S2 → 次日承接 S3 → 二次启动确认 S4
```

- **S1**：收盘价 = 涨停精确价（容差 0.005）+ 前 20 个交易日无收盘涨停 + 日线 ≥ 25 根。
- **S2**：5 日量能 ≥3 倍、成交额 ≥2 倍、收盘 ≥ 开盘、非高位巨量（`pos60 ≥0.95` 且量能 ≥6 倍）、
  涨停质量非 C 级。逐条列出剔除原因，不能只说「不符合」。
- **S3**：A 强势承接 20 / B 平开换手 14 / C 低开反包 10 / D 失败 0（D 转 S7）。
- **S4**：支撑未破（≥首板收盘 ×0.93）+ 缩量整理（≤首板量 0.75）+ 区间不下移 + 收盘突破上沿 +
  放量 ≥1.5 倍 + 额增 ≥1.3 倍 + 板块 5 日 >−3%，七项里五项必须同时成立。

评分**分母随阶段变化**：S1/S2 分母 55、S3 75、S4 100，归一化后 ≥90 S / ≥80 A / ≥70 B / ≥60 C / 其余淘汰。
未验证维度在 `detail` 里记 0 分并标注「该阶段尚未发生」，**不能留满分**——否则「承接 20/20」
会被读成已经算过分了。

状态机跨日落库（`limitup_pool` 表）：S1→S2→S3→S4→S5→S6，失败分支 S7/S8/S9。
同日重跑必须幂等（`first_board_date` 或 `updated_date` 等于当日就跳过），
`first_board_*` 只在新一轮首板时重置。S3 与 S10 是保留位，EOD 流程里不会出现，别去找。

数据完整度上限 12/17 ≈ 0.706（缺首封时间、首封时刻、炸板次数、封单金额、分时均价），
置信最高 C；缺失一律 `None`，**绝不填 0**（`seal_amount=0` 会被读成「封单为零」）。
`vwap` 是「额/量」全天均价（日线代理），不等于分时均价线，后者在 `intraday_vwap` 且恒为 `None`。

验收：`python scripts/verify_limitup.py`（17 项，含 8 个交易日跨日回放，否则 S3/S4 永远是 0）；
单测 `tests/test_limitup.py`（33 项，全合成数据）。

## 模块G 通达信桥接

独立 `Tongdaxin Bridge` 子模块，与主程序解耦，作为可选进程或线程启动。

能力：接收当前选中股票、自选股、条件选股结果、自定义公式信号、代码与名称，写入指定分组，自动去重，记录接收时间，连接状态检测，断线自动恢复与日志。

优先实现通道：CSV 导入 → JSON 文件监听（watchdog）→ 本地 HTTP 接口 → WebSocket 推送。DDE、共享目录等按实际安装版本评估，不得假设各版本协议一致——所有通道统一经适配器层，实现细节见 `references/data-adapters.md`。

**反向联动（已落地，2026-11-09）**：模块 G 目前只做了「桥接 → 本程序」的入库方向；
「本程序 → 通达信」由二级页面（强势回调 / 涨停四阶）的「通达信联动」按钮完成，
`GET http://127.0.0.1:3000/tdx?code=<6位>`，实现见 `app/services/tdx_link.py` +
`app/ui/tdx_link_button.py`。三条硬口径：只发一次、不重试；只发 6 位代码（剥 `.SH/.SZ`）；
**空 ProxyHandler 直连**（`HTTP_PROXY` 会把 127.0.0.1 转给代理，代理回 200 就是假成功）。
桥接返回体不解析，也不据此改任何本地状态。

## 模块H 本地分组记忆

默认分组：龙头核心池、市场最高板、连板晋级池、首板观察池、二波启动池、强势趋势池、主线题材池、龙虎榜观察池、盘中异动池、待复盘股票池。

分组操作：新增、删除（需二次确认，非空分组提示股票数）、重命名、拖动排序、股票移动、批量导入（粘贴代码/CSV/桥接推送）、批量删除、分组复制、独立布局、自动保存、重启恢复。

硬性要求：关闭软件再次打开，恢复上次的分组、组内顺序、当前选中分组、观察状态、图表布局与周期、预警条件、窗口位置与尺寸。任何配置项禁止只驻留内存。
